# Readout glossary — the standing language bridge

Studio and pilot terms translated once, so every readout says the same thing the same way. A readout copies the rows it needs into its "Terms used here" section. Grow this file as terms appear; never define a term two ways.

| Term in the artifacts | In a readout |
|---|---|
| seat | one of the seven specialist reviewers or authors in the studio (the Strategist, the Discovery reviewer, the Insights reviewer, Growth, Business, Delivery, Leadership) |
| artifact | the document a seat writes and hands forward |
| pass | one run of one seat or check; "run" in a readout |
| loopback | sending a document back to its author for a specific fix |
| co-sign | a second reviewer checking one named section, claim by claim, before the document counts as done |
| audit | a fresh reviewer reading the whole finished document and answering one fixed question about it |
| stake | the one question an audit is responsible for answering |
| MATERIAL | the reviewer considers this serious enough to need a fix or Sean's explicit acceptance |
| NOTE | worth recording; no fix required |
| gate | a red-team check run by a different vendor's model on a milestone; it can pass, pass with acceptances, or fail |
| acceptance | a serious finding Sean chooses to live with, with his reason written down |
| revision | the same document rewritten in place after a fix; earlier versions survive only in the run records |
| stale / cascade | a fix upstream makes the documents below it out of date, so they get rewritten in order |
| loop cap | Sean's rule: one repair round per document per check, then remaining findings go to him or the gate |
| ledger entry | the written record of one decision, with its options, its reason, and what the seat leaned on from the reading list |
| the canon | the studio's reading list of product books and essays; "leaned on the canon" means the seat used an idea from it, in its own words |
| Voluntary Return | a tester opening the app on a day with no completed workout, with no prompt from the app and no recent contact from Sean |
| countable tester-day | a day for one tester on which the app was known to be alive and the day can be classified, so a return on it counts |
| unclassifiable tester-day | a day we do not have enough information to judge; reported separately, never counted as a return or a non-return |
| terminal foreground reconciliation | one final refresh of workout data while the app is open, at the scheduled closing session |
| Earned Progress | character strength awarded once for a workout and never taken back |
| Eligible Source | an app or device whose workouts are allowed to earn progress: Apple Watch, manual Apple Health entries, or a verified third-party exporter |
| Reconciliation | the app comparing Apple Health's workouts with what it has already rewarded; guaranteed only when the app is opened |
| Import Summary | the single screen showing which workouts were just rewarded and what the character gained |
| pre-exposed testers | the two people who see the app in observed sessions before the two-week pilot, so their returns cannot be read the same way |
| precondition | a fact cheap to check before committing, with a plan for each answer; not a bet |
| bet | a choice with a real alternative, a reason, and a stated way it could be proven wrong |
| labeled wish | a rule the team is keeping without pretending this pilot can prove it |
| P0-equivalent | a finding that, if true, would make the pilot unsafe to share or would make its main question unanswerable |
| implementation hold | evidence only a built app can produce; recorded as an obligation for the build, not a defect in the plan |
