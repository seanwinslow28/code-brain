# Pencil & Prompt migration audit: what moves into `pencil-and-prompt`

**Question.** Which skills, docs, folders, scripts, hooks and private-layer files in `code-brain` and in `~/Code-Brain/anima/` should be moved, copied, adapted or left behind to set up `~/Code-Brain/pencil-and-prompt/` (private repo, own Obsidian vault, own CLAUDE.md and AGENTS.md)?

**Method.** Read-only. Every file below was read in the main checkout on the MacBook Pro (the canonical host for the private layer, map #158 Notes). Dependency claims cite `path:Lnn`. Private files are named by path, size and count only; nothing from the corpus, transcripts, sidecars, ledger or cheese bank is quoted. Verified on the day: `python3 scripts/validate.py` passes (56 pre-existing secret-pattern warnings, none in the rows below); `launchctl list` on this machine shows only `com.sean.oracle-reminder` and the unrelated `the-oracle` / `sourdough` jobs loaded, so the scheduled fleet is on the Mac Mini as the map says.

## Summary

1. **Nothing has to move on day one.** Almost every writing skill can be *copied* into `pencil-and-prompt` and become canonical there, while the `code-brain` copy is frozen for its two remaining consumers: the Professional lane (job-hunt work the sweep kept here) and the Sunday Knowledge Lint. Only the private brain (`creative-studio/content-machine/*`) and the studio folder (`vault/20_projects/substack-studio/`) are real *moves*, and both are two-step (copy, verify checksums, then retire the old path once consumers are re-pointed).
2. **The single biggest breakage risk is the retirement registry.** `.claude/skills/content-machine/runtime-retirements.toml` lists 27 scan targets across five skills, the studio CLAUDE.md and an agents-sdk script; the scanner raises on any missing path ([check_runtime_retirements.py:71-72](../../../.claude/skills/content-machine/check_runtime_retirements.py)) and Knowledge Lint runs it every Sunday ([knowledge_lint.py:73-82, 392-435](../../../agents-sdk/agents/knowledge_lint.py)). Move any scan target and every lint report carries a HIGH `runtime-retirement-check-error`. Every one of those files is therefore `copy` or `adapt`, never `move`, until #306 or the scaffold ticket re-points or retires the registry.
3. **The on-demand Oracle is the second cluster.** Its three scripts hard-code the repo root by directory depth, the private brain under `creative-studio/content-machine/`, the sidecars under `~/.creative-harness/partner-sessions/`, and two `agents-sdk/` tools plus its `.venv` for the tier audit and the TTS render. It moves as a unit, with paths re-pointed, or it stays.
4. **Second ruling for Sean:** his eleven pre-AI screenplays are tracked in public `code-brain` at `vault/40_knowledge/references/screenwriting-skill-building/Seans-Old-Scripts/Markdown/` (27 files) and are the corpus's registered pointer vein. Copy them into the voice library either way; whether they stay public is his call, not this audit's.
5. **Anima gives the writing room five things and keeps everything else:** its philosophy page, the Studio Brief template's "what this is NOT" block, the anti-distillation contract behind the vendored screenwriting voice, the style-register authoring playbook as the model for frozen Drop briefs, and the four register research notes as craft reading. The pipeline, characters, runs, evals and Flow UI only work inside anima; Drop battery animation briefs get *run* there and *written up* in `pencil-and-prompt`.
6. **Decision the scaffold ticket must take first:** whether the private repo *commits* the brain (recommended: it is the point of a private home, and the brain finally gets version control) or keeps the gitignore split. Everything in section 6 assumes commit-with-backup; if Sean keeps the split, replicate the `PRIVATE LAYER` block before the first copy.

## How to read the table

- **Call.** `move` = the new home becomes the only copy (always two-step here). `copy` = both repos hold it; the note says which is canonical. `adapt` = copy or keep, but something has to change for it to work. `leave` = stays in `code-brain` or anima, cited by path from the new home.
- **Privacy class.** `tracked` (public on GitHub today), `gitignored private layer` (on local disk only, under the `.gitignore` `PRIVATE LAYER` block, [.gitignore:124-333](../../../.gitignore)), `local-only sidecar` (outside any repo, under `~/.creative-harness/` or `~/.claude/`). Anima rows say `tracked (anima, public)` where relevant.
- **Path law that decides half the rows.** The Python in these skills finds the repo root by *directory depth*, not by name: `sweep.py:31` uses `parents[3]`, `news_lane.py:47` `HERE.parents[2]`, `coined_lines.py:50` `parents[4]`, `build_baseline.py:36` and `build_rewrite_band.py:30` `parents[4]`, `trace/machine.py:22` `HERE.parents[3]`, `x/stimulus.py:68` `HERE.parents[3]`. If `pencil-and-prompt` keeps the `.claude/skills/<skill>/...` layout, every one of these resolves to the new repo root without edits. What does not travel automatically is the second half of each constant: the brain path (`creative-studio/content-machine/...`), the studio path (`vault/20_projects/substack-studio`), the `agents-sdk/` tools, and `productcraft/trace`.
