This article outlines a structured planning prompt designed for a fresh Claude Code session to execute "Topic 20," a project focused on benchmarking new Ollama models across a three-device hardware fleet and implementing a power-efficient Wake-on-LAN (WoL) architecture. The central thesis is that by using a specialized `/writing-plans` skill, the agent can generate a highly detailed, executable, and unambiguous plan that automates the testing of newer models (such as Qwen 3.5/3.6 and Gemma 4) while adhering to strict operational constraints, specifically the need to minimize electricity costs by ensuring the high-power Alienware desktop remains powered off when not in use.

The proposed plan relies on several key supporting components: a multi-tier hardware evaluation, a rigorous benchmarking suite, and a specific network architecture. The hardware fleet includes a MacBook Pro M4 Max (Tier A), a Mac Mini M4 Pro (Tier B), and an Alienware with an RTX 4090 (Tier C). The benchmark suite is designed to measure tool-calling correctness (using at least 20 prompts), tokens per second, memory footprint, agentic-loop reliability, and long-context degradation (using a 32K-token "needle in a haystack" test). Specifically, the agent must confirm the Alienware's operating system and current power management state, and it must determine if the benchmark success thresholds (e.g., an 80% tool-call accuracy) are acceptable to the user.
