This report details the technical configuration required to integrate the Pi terminal-based coding agent (pi.dev) with a local or LAN-reachable Ollama instance. The central thesis is that Pi treats Ollama as a first-class, OpenAI-compatible provider, allowing users to leverage local hardware—such as a Mac Mini or Alienware desktop—to run agentic workloads with low latency and reduced "agentic hover."

The integration relies on modifying the `~/.pi/agent/models.json` file to point to an OpenAI-compatible `/v1` endpoint. Key implementation details include using `http://localhost:11434/v1` for local setups or utilizing Tailscale MagicDNS addresses for remote access, provided the Ollama host is configured with `OLLAMA_HOST=0.0.0.0`. For performance and reliability, the report highlights that context window management (via `num_ctx`) must be handled within the Ollama `Modelfile` rather than the Pi config, and recommends specific models like DeepSeek-Coder-V3 for tool-calling reliability or Qwen3-14B for speed. Furthermore, the report notes that local M4 Pro hardware can achieve 40–70 tokens per second with a time-to-first-token of under 200ms, often outperforming cloud providers in responsiveness.

While the integration is functional, several technical "gotchas" and areas for further investigation remain. Users are advised to set a `keep_alive` duration (e.g., "5m") in Ollama to prevent model unloading and must ensure the `baseUrl` includes the `/v1` suffix to maintain streaming compatibility for tool-calling. Additionally, while Llama-4 is emerging as a strong performer, its stability regarding specific Pi "skills" is still evolving. The report concludes by suggesting that users monitor for truncation issues and provides a template for a fallback configuration to Anthropic should the local provider fail.
