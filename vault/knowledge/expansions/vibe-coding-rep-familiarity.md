## What this is

Critiques from two external reasoners (gpt-5.5 via Codex CLI, Gemini 3 via Anti-Gravity CLI) of [[vibe-coding-rep-familiarity]]. The synthesizer describes what the concept is; this expansion proposes what's missing.

## From Codex (gpt-5.5)

1. **Add “visible-instrumentation fluency,” anchored on Bret Victor’s talk *Inventing on Principle*.**  
   Current concept treats rep familiarity as “I can use named tools in public.” That is too vendor-shaped. Add a stronger facet: Sean should demonstrate that he can make an agentic system *legible while it is running*.

   Pattern to add: “Don’t just show the tool session; show the state, traces, intermediate artifacts, failed branches, and recovery decisions as first-class UI.”

   This unlocks a better portfolio artifact: an **agent workbench demo** where Code-Brain, intent-engineering MCP, or the vault critic exposes live traces, cost caps, model routing, rejected outputs, and escalation rules. That reaches beyond “I have reps in Cursor/v0” into “I can design inspectable agent systems,” which is much more senior.

2. **Add “deliberate practice for tool fluency,” anchored on K. Anders Ericsson, Ralf Krampe, and Clemens Tesch-Romer’s paper *The Role of Deliberate Practice in the Acquisition of Expert Performance*.**  
   The current article says “45-minute unedited session,” but not how Sean gets better or proves progression. Missing piece: reps need constraints, feedback loops, scoring, and difficulty ladders.

   Pattern to add: “Each public session should have a target skill, a failure mode, a scoring rubric, and a before/after delta.”

   This unlocks a **vibe-coding training log** or **agentic-engineering kata series**: 10 constrained sessions such as “recover from bad generated architecture,” “force an agent to write tests before code,” “replace brittle prompt instructions with executable guardrails,” or “ship one MCP affordance in 45 minutes.” The current concept can produce demos; this produces evidence of expertise formation.

3. **Add “anti-demo realism,” anchored on Lucy Suchman’s *Plans and Situated Actions*.**  
   The hidden weakness in “tool familiarity” is that demos reward smooth planned action, while real agentic work is situated, interrupted, partial, and negotiated with messy context. Sean’s actual edge is not that he can use Bolt or Cursor; it is that he has lived through launchd failures, merge conflicts, context injection limits, cost caps, disabled agents, and citation collapse.

   Pattern to add: “Show the moment the plan breaks, then narrate the situated repair.”

   This unlocks a stronger Substack/portfolio genre: **failure-forward field notes**. Example artifact: “I Tried to Make My Knowledge Vault Critic Generative, and It Kept Summarizing Me Back to Myself.” That lets Sean sound like an operator of real agent systems rather than another candidate performing tool tourism.
