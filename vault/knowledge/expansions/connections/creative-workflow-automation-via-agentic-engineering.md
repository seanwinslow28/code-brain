## What this is

Critiques from two external reasoners (gpt-5.5 via Codex CLI, Gemini 3 via Anti-Gravity CLI) of [[creative-workflow-automation-via-agentic-engineering]]. The synthesizer describes what the concept is; this expansion proposes what's missing.

## From Codex (gpt-5.5)

1. **Add “creative constraints as generators,” anchored on Brian Eno and Peter Schmidt’s _Oblique Strategies_**

   The concept currently treats agents as automation leverage: Sean has a workflow, agents accelerate or critique it. Missing is the opposite mode: agents that introduce productive constraint, interruption, and lateral pressure.

   Add a pattern like: “When the creative system converges too quickly, inject a constraint card that changes the problem, not the output.” Anchor it on Brian Eno and Peter Schmidt’s _Oblique Strategies_ card deck, not generic brainstorming.

   **Unlocks:** a shippable “Oblique Agent” spec or Substack essay: _My Agents Are Too Helpful_. This would let Sean show creative agency design where agents are not assistants, but controlled sources of friction. That is a more interesting artifact than “AI helps me make sprites faster.”

2. **Add “situated action beats plans,” anchored on Lucy Suchman’s _Plans and Situated Actions_**

   The article assumes intent can be specified, then executed through agents. Suchman is the contradiction Sean needs: plans do not govern action as much as they retrospectively rationalize action inside a changing situation.

   Add a critique layer: “Intent specs are not command structures; they are navigational artifacts agents must reinterpret against live context.” Anchor it on Lucy Suchman’s _Plans and Situated Actions: The Problem of Human-Machine Communication_.

   **Unlocks:** a stronger intent-engineering MCP artifact: not just “agent reads a spec and tells you what’s missing,” but “agent detects when the plan has stopped matching the situation.” That becomes a portfolio-grade demo: feed it a stale PRD, changing constraints, and runtime traces; it outputs drift, invalid assumptions, and escalation points.

3. **Add “liveness / live coding as creative system design,” anchored on Sam Aaron’s Sonic Pi work**

   Sean has automation, pipelines, and scheduled agents. Missing is liveness: the creative system as something performed, steered, and improvised in real time. That matters because creative workflow automation can otherwise read like batch processing with better taste.

   Anchor this on Sam Aaron’s Sonic Pi project and talks/writing around live coding music, especially the idea of programming as performance rather than production plumbing.

   Add the mode: “Agents should expose playable controls, not only produce finished artifacts.” Sentence pattern: “The interface should let Sean conduct the pipeline mid-flight: raise variance, freeze style, branch a take, replay the decision trace.”

   **Unlocks:** an executable demo genre: a live “creative cockpit” for 16BitFit sprites or Substack headers, where Sean manipulates agent parameters while outputs evolve. This would move the concept from “agentic automation” into “agentic creative instrument,” which is much rarer and more legible as IC-level product-engineering taste.
