## What this is

Critiques from two external reasoners (gpt-5.5 via Codex CLI, Gemini 3 via Anti-Gravity CLI) of [[ai-prototyping-and-vibe-coding-interview-format-synergy]]. The synthesizer describes what the concept is; this expansion proposes what's missing.

## From Codex (gpt-5.5)

1. **Add “interview as work-sample theatre,” anchored on Alison Green’s _Ask a Manager_ hiring writing and Laszlo Bock’s _Work Rules!_**

The current concept treats vibe-coding as “show AI fluency.” That is too thin. Add a pattern where the candidate deliberately stages the interview as a work-sample: clarify success criteria, expose tradeoffs, narrate risk, make reversible decisions, and leave behind a usable artifact.

Sentence pattern: “In a vibe-coding interview, the goal is not to finish code fastest; it is to make your judgment observable under realistic ambiguity.”

This unlocks a **vibe-coding interview runbook**: opening script, decision log template, test strategy, “when I let the agent drive vs when I intervene,” and a post-interview artifact packet. Sean currently has “practice AI-assisted coding”; this adds a hiring-theory frame for proving judgment.

2. **Add “deliberate practice loop,” anchored on Anders Ericsson, Robert Pool, _Peak: Secrets from the New Science of Expertise_**

The missing facet is practice design. “Prioritize practicing AI-assisted coding” is generic because it does not define reps, feedback, difficulty, or failure modes. Add Ericsson-style deliberate practice: isolate one interview skill per session, create immediate feedback, push just beyond comfort, and maintain a defect log.

Concrete mode: “Vibe-coding reps should be scored on one constraint at a time: requirements clarification, agent instruction quality, test-first discipline, recovery from bad generation, or verbal explanation under time pressure.”

This unlocks an **executable practice regimen**: 20 timed drills, scorecards, replay prompts, and a “failure taxonomy” for AI-native interviews. Sean can turn this into a portfolio artifact showing he does not merely use agents; he trains himself as an operator of them.

3. **Add “anti-vibe critique,” anchored on Peter Naur’s 1985 essay “Programming as Theory Building”**

The current connection accepts vibe-coding’s premise too easily. Naur gives Sean the contradiction: programming competence is not just producing code; it is building and holding a theory of the system. In an AI-assisted interview, the risk is that the model produces plausible code faster than the candidate can build ownership.

Add this claim: “The strongest AI-coding candidate demonstrates theory ownership: they can explain why the generated solution is shaped this way, what would break it, and how they would extend it tomorrow.”

This unlocks a **Substack essay or interview one-pager** contrasting “vibe coder” with “theory-holding agentic engineer.” It gives Sean a sharper market position: not “I code with AI,” but “I use AI without surrendering system understanding.”
