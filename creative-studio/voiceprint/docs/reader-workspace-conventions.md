# Reader Workspace Conventions

The on-disk contract shared by every VoicePrint command and skill. Commands are
stateless across invocations — Cowork starts each `/command` fresh — so **the
files below ARE the memory of the process.** Every command reads `pile-state.json`
first to know where the reader is, does its work, then writes its artifact and
updates state.

All paths are relative to a single root the reader establishes in `/voiceprint-start`:
the `voiceprint/` directory inside whatever folder they opened in Cowork.

```
voiceprint/
├── my-voice/                      # THE DELIVERABLE (built by /voiceprint-synthesize)
│   ├── SKILL.md
│   └── references/
│       ├── reference-universe.md
│       ├── cheese-bank.md
│       └── voice-samples.md
└── _work/                         # working state — the process's memory
    ├── pile-state.json            # single source of truth for "where am I"
    ├── interview-transcript.md    # raw Q&A from /voiceprint-interview (A)
    ├── gauntlet-reactions.md      # the 10 lines + the reader's reactions (B)
    ├── mined-samples.md           # pasted pre-AI writing + extracted moves (C)
    ├── refine-log.jsonl           # one JSON line per refine round (E) — diff metrics
    └── dashboard.html             # regenerated by start/refine; reader opens it
```

## pile-state.json schema

The contract every command reads and writes. Example:

```json
{
  "schema_version": 1,
  "reader_label": "anon",
  "root": "voiceprint/",
  "created": "2026-06-08",
  "updated": "2026-06-08",
  "preferences": {
    "em_dashes": "keep",
    "profanity_ok": null
  },
  "stages": {
    "interview":  { "status": "complete",     "artifact": "_work/interview-transcript.md", "updated": "2026-06-08" },
    "gauntlet":   { "status": "complete",     "artifact": "_work/gauntlet-reactions.md",   "updated": "2026-06-08" },
    "mine":       { "status": "incomplete",   "artifact": null, "cold_start": false },
    "synthesize": { "status": "not_started",  "artifact": "my-voice/", "generated_from": [] },
    "refine":     { "status": "not_started",  "rounds": 0, "last_diff_pct": null }
  },
  "next_best_action": "Run /voiceprint-mine to feed in a chunk of your pre-AI writing."
}
```

### Field rules

- `stages.<name>.status` is one of: `not_started`, `incomplete` (started, not enough
  evidence yet), `complete`.
- `mine.cold_start: true` records that the reader had little/no pre-AI writing and
  the skill should be flagged outline-grade until real samples arrive.
- `synthesize.generated_from` lists the artifact paths the last synthesis read, so
  re-synthesis knows what changed.
- `refine.rounds` and `refine.last_diff_pct` drive the dashboard's "is it sharpening?"
  readout. Lower `last_diff_pct` over rounds = the voice is converging.
- `preferences.em_dashes`: `"keep"` (default) or `"drop"`. Elicited, never assumed.
  This is how the bundled humanity-pass avoids imposing one writer's taste.
- `next_best_action` is a single human-readable sentence; `/voiceprint-start`,
  `/voiceprint-status`-equivalents, and the dashboard all surface it.

## How a command uses the contract

1. **Read** `voiceprint/_work/pile-state.json`. If absent, tell the reader to run
   `/voiceprint-start` first (except `start` itself, which creates it).
2. **Do the work** (interview / gauntlet / mine / synthesize / refine).
3. **Write** the artifact to its path above.
4. **Update** the matching `stages.<name>` block, bump `updated`, and recompute
   `next_best_action`.
5. Never silently overwrite a `complete` artifact — append or confirm first.

## Why files, not memory

This is the answer to "how does an interview keep state between turns." Within one
`/command` run, the live conversation holds context. Across commands, only the files
persist. Treat `pile-state.json` as the join key and the `_work/` artifacts as the
evidence pile the synthesis step reads. Nothing about the reader lives only in a
model's head.
