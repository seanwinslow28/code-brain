# Control Architecture — Explanation

## What is this?

A ~1,700-word reframing of infrastructure I already run — budget caps, circuit breakers, keychain-gated credentials, Pushover escalation, and append-only JSONL ledgers — as the **Authority / Recovery / Audit** control trinity that Forward-Deployed and enterprise AI-PM buyers look for (Nate Jones §3.7). The artifact is [`agents-sdk/docs/CONTROL_ARCHITECTURE.md`](CONTROL_ARCHITECTURE.md): three sections mapping 1:1 to the trinity, a Mermaid sequence diagram of the four-surface chain (breach → block → ledger write → Pushover page → rollback), and a worked example. It ships with a runnable demo at [`tools/governance-demo/`](../../tools/governance-demo/) — `replay_budget_breach.py` replays three synthetic fixtures (`allowed` / `over_budget` / `missing_auth`) through the real control shape, plus a sanitized declarative policy example at [`agents-sdk/config/authority.example.yaml`](../config/authority.example.yaml). It cites real implementation throughout: the cap cascade in [`config.toml`](../config.toml) (`per_query` → `daily_cap_usd = 20.00` → `monthly_cap_usd = 50.00`), [`lib/keychain.py`](../lib/keychain.py), [`lib/pushover.py`](../lib/pushover.py), the `RouteUnavailable` circuit breaker in [`lib/hybrid_router.py`](../lib/hybrid_router.py), the `vault/health/*-spend-*.json` ledgers, and the `valid_until` provenance fields in [`lib/concept_edges.py`](../lib/concept_edges.py). It is the FDE-shaped artifact — a direct match to the Anthropic FDE Boston JD — and it closes my one "beginner" gap (cost economics) with a worked example.

## Why this approach?

Three options were on the table after the 2026-05-16 LLM council surfaced the gap (Gap-Fill 4 of 5). **Option A — build new governance infrastructure to demo** loses on honesty and time: the controls already exist and enforce a $50/month ceiling on a live fleet; building parallel demo infrastructure would be theater, and an FDE would smell it. **Option B — write the doc with no runnable artifact** loses because "I have controls" is a claim, and FDE buyers discount claims; a 60-second `over_budget` replay that pages a real phone is evidence. **Option C — name the existing infrastructure as the trinity and add the smallest possible runnable demo over it** wins: ~80% of the substance already shipped, so the work is the *naming* plus a worked example, and the demo exercises the real control shape rather than a mock. The load-bearing constraint inside option C is a credibility guardrail the council flagged: the local-cloud router gets exactly **one paragraph** under Authority ("authority over which brain runs which task"), with an explicit deferral, and is never framed as an "agent operating system" or "runtime architecture." I am a beginner-to-intermediate coder; framing ~100 lines of routing logic as systems architecture invites senior engineers in a technical screen to grill me on concurrency, distributed caching, and thread-locking — fights I can't win at my level. The restraint is the credibility. Trade-off accepted: the demo is deliberately stubbed and synthetic (no real LLM spend), which a careless reader could mistake for hand-waving — mitigated by stating the stub boundary loudly in the README and the doc.

## What would break?

**(1) The demo's stubbed runner drifts from the real fleet's exit-code semantics.** The demo adopts exit `7` = budget breach and `3` = auth denied as conventions for an unambiguous worked example; the production fleet enforces hook codes `0/1/2` plus typed exceptions (`RouteUnavailable`, budget-cap aborts). A reader who clones the repo and finds no `exit(7)` in the fleet could feel misled. *Detection signal:* the boundary is stated explicitly in three places (the doc's "Worked example" honesty note, the README "stub boundary" section, and the script's module docstring). *Mitigation:* the honesty note is load-bearing copy, not a footnote; a future hardening step is an integration test that reads the actual exit code from one real (cheap) Job Feed run and asserts the demo's `allowed`/`block` *decisions* match the real `RouteUnavailable` / cap-abort behavior, even though the integer codes differ by design.

**(2) Cited line numbers and config keys rot as the fleet evolves.** The doc cites `config.toml` keys (`daily_cap_usd`, `fallback_disabled`, `cost_cap_usd_hard`) and `hybrid_router.py` (L41) by name; config drifts (these very caps moved from the spec's L340/L366 to L460/L486 between planning and build). *Detection signal:* a broken-link or grep check during any future edit pass; `scripts/validate.py` already scans the repo. *Mitigation:* citations are by key name and file, not only by line number, so a key rename is a find-and-replace rather than a silent staleness; the worked example leans on behavior (cap cascade) over exact integers.

**(3) Over-reach on the trinity completeness.** Enterprise buyers may expect controls the fleet doesn't have (rate limiting, least-privilege scoping beyond credential presence, tamper-evident audit logs, secret rotation). Claiming "full control architecture" would over-state a one-laptop fleet. *Detection signal:* the LLM council stress-test (premium profile) is run against the doc specifically to surface this gap before any human reader does. *Mitigation:* the doc scopes itself explicitly ("sized to one laptop and one phone") and frames the trinity as the three controls that matter most for autonomous spend, not an exhaustive enterprise control catalog.

## What did I learn?

Control architecture is mostly the discipline of writing down what's already implemented, not building new infrastructure. The hard part wasn't the controls — those had been quietly enforcing a budget for two months — it was resisting the urge to make them sound bigger than they are. The single most valuable edit in the whole artifact is a subtraction: cutting the temptation to call the router an "agent OS." The travel-able insight is that for a beginner-to-intermediate engineer, credibility is won by precisely scoping the claim to what the code actually does and saying the boundary out loud — the honesty note about exit code 7 makes the demo *more* persuasive, not less, because it proves I know exactly where the demo ends and the real system begins. Naming beats building when the thing is already built.
