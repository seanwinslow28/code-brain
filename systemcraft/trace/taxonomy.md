# taxonomy — rung 1 of the ladder, Systemcraft

The tracked vocabulary a Systemcraft engagement's `trace/labels.md` draws its `failure_code` column from. This is Systemcraft's own file, for the seat failure modes its own labels earn. The families every studio shares (today the **process-waste** family) live in the shared kit's [craftwork/trace/taxonomy.md](../../craftwork/trace/taxonomy.md), and `check.py` reads both ([studio.py](studio.py) names this file). Shapes of failure only: no engagement content, no private text, nothing a recruiter should not read.

**Rung 1 has not opened for Systemcraft.** The file was created on 2026-10-01 when Systemcraft adopted the shared law ([craftwork build 4](https://github.com/seanwinslow28/code-brain/issues/327)) and began tracing from eng-005. A seat failure mode lands here only the way Productcraft's did ([#299](https://github.com/seanwinslow28/code-brain/issues/299)): read from about thirty labelled passes, proposed with its counts, and ratified by Sean with a date. Productcraft's modes are not inherited. They were earned on a different bench, and a code earns its place here only from Systemcraft's own labels.

Until then a label carries a shared process-waste code or leaves the column blank. A blank column is the normal state, and it passes.
