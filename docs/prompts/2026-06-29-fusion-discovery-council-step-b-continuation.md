## TASK (this session) — D2: receipts UI (verification provenance per card)

**Why this is next:** it's the **last Step-B item**, it's **$0**, and it **cashes in E3**. Every rendered card already passed the anti-fabrication gate, and after E3 the corroboration counts are *honest* (distinct-domain-keyed, near-dups merged). D2 surfaces that gate work *on the card itself* so a reader can see at a glance how well-evidenced each opportunity is — the "verified, not hallucinated" promise made visible, which is the tool's brand.

**Goal:** add a compact, scannable **receipts line** to each ranked card in **both** ledgers (PM `IdeaCard` in `render.py` and substack `PostAngle` in `render_substack.py`): verification status, corroboration depth, and a recency badge. The data all already lives on `score: ScoreBreakdown` — D2 is a **render-layer feature, no new logic, no model call, no gate change.**

**The load-bearing design nuance to brainstorm with Sean (think before you build):** every card that renders has *already* passed the gate (`verified=True`), so a bare "✓ verified" checkmark is true for 100% of cards and therefore says nothing. The receipt's value is the **gradient** — *how well* corroborated (K independent domains), *how fresh* (recency badge), *how much* model consensus — not a binary stamp. Design the receipt to communicate the gradient honestly, and keep it from implying a precision the evidence doesn't have (mirror D4's "not a severity/confidence score" discipline).

**`RESEARCH →` before locking the shape (the one load-bearing unknown — keep it tight, this is lighter than prior passes):**
- **Trust / provenance / "receipt" UI patterns for evidence-backed claims** — how do credible products show *provenance and corroboration depth* on a card (source-count chips, freshness/staleness badges, confidence as a gradient not a checkmark) **without** manufacturing false precision? Specifically: **recency-badge thresholds** (what age/score → "fresh" vs "recent" vs "aging" vs "stale" — and reuse `scoring.py`'s `HALFLIFE_DAYS`/`RECENCY_FLOOR` semantics rather than inventing parallel constants), and **corroboration-tier labels** (how many independent domains reads as "single-source / corroborated / well-corroborated"). Fold findings into the spec with citations + a vault note (mirror the three exemplars). If the shape is obvious after one brainstorm round and the badge thresholds are a clean mapping off existing constants, it's fine to keep the research pass short — don't let it balloon a render change.

**Build discipline (DO THIS IN ONE PASS — flagged so it isn't split awkwardly):**
- **Make it DRY across both renderers from the start.** Both ledgers need the same receipt; build a single shared deterministic helper module (e.g. `council/discovery/receipts.py`, modeled exactly on how `whitespace.py` is shared by `render.py` + `render_substack.py`) with one `receipt_line(score, ...)` (or small set of) entrypoint(s) both call. Do **not** write the formatting twice and refactor later — the whitespace.py precedent is right there.
- **Reuse `scoring.py` constants for the recency badge** (`HALFLIFE_DAYS`, `RECENCY_FLOOR`, and the `score.recency`/`score.evidence_date` already computed) — do not introduce a second, drifting set of recency thresholds. If you add badge-tier constants, put them where they're discoverable and sensitivity-flagged like the scoring constants.
- **Honesty invariants (keep sacred):** the receipt may only restate what the gate + scoring already established; it must never imply a card was verified more strongly than its distinct-domain count supports, never show a confidence number as harder than `confidence` is, and (consistency with D4) carry a one-time framing that corroboration depth is evidence breadth, not proof of importance. A single-domain card must *read* as single-source, not get a reassuring green check.
- **$0, deterministic, hermetic tests.** Update SKILL.md §4 (FRAME/output) to describe the receipts, CHANGELOG, and add tests for both renderers (PM + substack) covering: a well-corroborated fresh card, a single-source card (must read as single-source), an aging/stale card (badge maps correctly), and the empty/zero-verified path (no receipts, no crash). Run `cd tools/llm-council && uv run pytest tests/ -q` (currently **233 passed, 1 skipped**) + `python3 scripts/validate.py`.
