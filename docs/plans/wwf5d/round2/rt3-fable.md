**The diagnosis.** The intents are right; the *execution ceiling* is low, and it's structural, not cosmetic. Three shared causes: (1) **the motion vocabulary is one native `<input type="range">` driving hand-rolled opacity/mask lerps** — every beat is a linear cross-fade or gradient wipe, so nothing moves the way pencil, paper, or a terminal actually behaves; (2) **the most impressive truths are simulated rather than performed** — the intent explainer *pretends* to audit (a counter eased 7→23) when a real deterministic auditor exists on npm; the animation explainer *never animates* — a run cycle that never runs, on a case study whose Engine Truth is "if the loop plays smoothly, it ships"; (3) **the craft is invisible at rest** — with no entrance beat and the scrubber hidden until JS opts in, a skimming recruiter sees a static image and may never discover the interaction. This spec fixes those three causes system-wide and works two exemplars in depth. The 2026-06-20 tooling-research doc's conclusion ("you already have the right architecture") remains true one level down — the PE contract, keyed-art pipeline, and registry are kept wholesale; what changes is the expressive ceiling on top of them.

## 1. The system-level elevation pattern — "Scene, not figure"

Every explainer graduates from *a diagram with a slider* to *a small scene that performs its system*. Three moves, applied per explainer only where they serve that explainer's intent:

**Move 1 — Medium-native motion.** Animate in the register's own physics: strokes that draw (not masks that wipe), a pencil that follows the stroke it's drawing, flipbook playback at real frame holds, stamps that thunk, terminal lines that land one at a time. Generic web-motion (parallax, blur, glow, springy overshoot everywhere) stays banned by taste even though the library ban is lifted — the template trap is an aesthetic, not a dependency list.

**Move 2 — The real-artifact beat.** Each explainer carries at least one *live, provenance-checked artifact from the actual system* — the daily-dated layer's honesty DNA applied to figures. The intent explainer runs the real shipped checklist; the animation explainer plays the real pose sheet at the pipeline's real 12fps; code-brain already has the 08:30; the-block already has the real hours. If a number or artifact can't be traced to a committed source, it doesn't ship (enforced at `validate`, below).

**Move 3 — Choreographed time.** Replace per-variant ad-hoc `t`-lerps with one authored, master timeline per explainer — named eases derived from `2d-animation-principles` (slow-in/slow-out, anticipation, holds), beats that overlap and settle like acting, plus a **one-shot viewport-entry overture** (≤1s: the scene "sets down" — ghost washes in, pencil taps the paper, stamp thunks) so the band visibly *lives* before any interaction. Entrances are already legal under the Licensed-Infinite-Motion Rule ("entrances are one-shot, hovers settle"); interaction itself stays 100% reader-driven (rollout rule 3 — no scroll-jacking, no autoplaying meaning).

### Recommended harness

**Primary: GSAP 3.13+ core, per-island lazy-loaded, with exactly three plugins — DrawSVGPlugin, MotionPathPlugin, CustomEase.** Reasoning, grounded in this medium:

- **The problem class is timeline choreography scrubbed by a scalar.** Every explainer is `render(t)` over staged beats with holds. `gsap.timeline({ paused: true })` + `tl.progress(t)` slots *directly* into the existing `wireScrubber` contract — the migration is additive, not a rewrite, and legacy variants keep working byte-identically.
- **The plugins are the pencil register's native verbs.** DrawSVG = self-drawing strokes (the "pencil-draws-itself" idea the original pilot brainstorm wanted and deferred); MotionPath = the pencil riding the live stroke tip with rotation; CustomEase = hand-authored spacing curves (`pencil-in`, `settle`, `thunk`) instead of stock power curves, which is where animation literacy becomes visible to a trained eye.
- **Licensing and weight are solved problems.** The repo's own adversarially-checked research (interactive-explainer-tooling-research-v1.md, verified live 2026-06-20) confirms GSAP is 100% free including all plugins since Apr 2025 (Webflow acquisition). Core + the three plugins ≈ **33–36 KB gz**, dynamically imported *only after* the reduced-motion gate and interactive opt-in succeed — no-JS and reduced-motion visitors download zero bytes of it.
- **Vanilla and framework-agnostic** — fits the Astro-island architecture; no React runtime tax (Framer Motion rejected for exactly that: it would drag React into every case-study page for islands that are deliberately vanilla).
- **On the prior ban:** the tooling doc's "keep it banned" verdict was a *compliance* note under the then-standing DESIGN.md rule plus a taste worry ("every agency site feel"). The rule is what Sean lifted; the taste worry attaches to *what* gets animated, not the tween engine — graphite strokes on the site's own paper, driven by the reader's hand, are the opposite of an agency hero section. The doc's factual findings (free, "DrawSVG/ScrollTrigger are the gold standard") now argue *for* adoption.

**Deliberately not adopted:** **ScrollTrigger** (scrub stays in the reader's hand via the native range — reader agency is a locked non-negotiable; viewport entry detection reuses the existing IntersectionObserver pattern, no plugin needed). **Rive / Lottie** — real tools, wrong pipeline: both require foreign editors (Rive editor / After Effects) that break the Gemini-pencil → key → composite art pipeline *and* the "the output is his" honesty layer; Rive additionally costs ~200 KB of WASM. **Three.js / WebGL** — not required by either exemplar; a graphite fragment-shader reveal (OGL, ~12 KB) stays a named, flagship-only stretch behind the same loader if the canvas brush edge ever proves insufficient to Sean's eye. **Lenis** — nothing to smooth. **Kept:** rough.js + rough-notation (already deps, already the graphite register's callout voice), canvas 2D (precedent: the 16bitfit LCD). **Sanctioned fallback:** anime.js v4 modular (MIT, roughly half the weight, covers ~80% of the need) *if and only if* the weight health-metric trips — a decision rule, not a second stack.

### How it fits the Astro explainer registry

Zero registry changes. Variants remain Astro components keyed by `explainer.interactive`; the `INTERACTIVE` map, the unknown-variant degrade-to-`<img>`, and the `{src, alt}` component contract are untouched. The frontmatter schema (`explainer.src/alt/caption/interactive`) is untouched — every enhancement is internal to variant components plus one new shared module.

### Fallback / performance / accessibility posture

Three tiers, unchanged in principle, sharpened in practice: **no-JS → static webp floor** (byte-identical to today); **JS + reduced-motion → variant-appropriate honest state** (full-static for scrub variants, instant-discrete-operable for stateful ones — both precedents already shipped); **JS + motion → the full scene**. New system-wide fix: the `.ie-scrub` block currently `display: none` → appears post-JS and *shifts the Methods band*; reserve its height (`visibility: hidden` reservation) so late enhancement on slow networks never causes CLS. Budgets: ≤45 KB gz added JS per case-study page, all post-opt-in; zero pre-opt-in delta; art assets reused (the 68 KB keyed run-cycle sheet is not regenerated); aspect-ratio height reservation kept. Accessibility: native inputs only (range/radio/button), `aria-live` narration per state change (the shipped pattern, extended), ≥44 px touch targets, amber `:focus-visible` rings, and the Playwright progressive-enhancement matrix extended to every new state.

## 2. Worked exemplar A — `animation-pipeline`: **"The Flipbook Test"**

**Communicative intent (unchanged, sharpened):** *the human authors the keys and the timing; the fleet fills the volume; the shipped thing moves and is recognizably itself.* Audience split: a recruiter must get the division of labor without reading; a creative technologist should recognize working animation practice, not animation-flavored decoration.

**Where the current build under-serves that intent:** the reveal is a soft `linear-gradient` mask — a Photoshop wipe, not drawing; the pencil is a static glyph translating on a straight line; the reveal order is strictly left-to-right, which is *rendering* order, not *animation* order — and the piece never plays, so the one claim the whole project stakes ("Act 1 shipped" — a loop that runs) is asserted by a stamp instead of demonstrated.

**The realization — three beats on one scrubber (the interaction shape stays ONE native range):**

1. **Brush-mask reveal.** The ink layer becomes a `<canvas>`: an offscreen mask canvas accumulates scribble-brush stamps along 2–3 pre-authored zigzag polylines per pose (a small committed JSON, authored once against the existing sheet the way `CHECK_TOPS` was calibrated); the pose art composites through it with `globalCompositeOperation: "source-in"`. The reveal edge is now *hatching that scribbles forward* — graphite laying down — instead of a gradient. The pencil SVG rides the live brush path via MotionPathPlugin with `autoRotate`, so it points along the stroke and lifts between poses. The ghost layer and the static floor are untouched.
2. **Pose-to-pose order.** The fleet inks the in-betweens in *animator's order*, not left-to-right: pose 1 stays pre-inked (the human key, today's `BASE`), then the breakdown, then the in-betweens fill between them — with the sublabel doing the teaching in mono (`KEY → BREAKDOWN → IN-BETWEENS`) as each lands. This costs almost nothing (the sheet is a horizontal strip; per-pose regions are rect masks) and is the single loudest craft signal on the page: anyone who has animated recognizes pose-to-pose workflow instantly, and a recruiter just sees drawings appearing in a confident, non-obvious order.
3. **The payoff — ▶ RUN THE LOOP.** At `t ≈ 1`, after the stamp lands, a play control arms (native `<button>`, ≥44 px, mono label). Pressing it plays the seven poses as a real pencil-test flipbook — one pose window, 12 fps with authored holds (an `SEQ`-style ms table, the 16bitfit precedent; contacts held longer, per `2d-animation-principles`), pause visibly available, playback owned by `licensedLoop` (in-view + tab-visibility gated), and any scrub input kills playback instantly. The section's Engine Truth — *"if the loop plays smoothly and the character is recognizably itself, it ships"* — stops being a quote and becomes the thing the reader just did. This adds a fourth entry to DESIGN.md's licensed-motion registry (*reader-initiated flipbook playback: media, not decoration; pause-visible; in-view-gated; reduced-motion never offers it*) — amended in the same PR, never silently.

Plus the system overture: on first viewport entry, the ghost sheet washes in left-to-right (a fast low-opacity pass of the same brush mask) and the pencil sets down at the reveal edge with a `settle` ease — one-shot, ≤1 s, entrance-class, reduced-motion exempt.

**Technique and why it fits:** GSAP master timeline (beats, holds, overlapping label/stamp choreography) + MotionPathPlugin (the pencil is *the* character of this explainer; a pencil that follows its own stroke is the medium demonstrating itself) + CustomEase (spacing is the project's literal subject — stock easing here would be an unforced error) + canvas 2D compositing (precedented in-repo; no WebGL needed for a hatched edge). Reduced-motion behavior is unchanged from today: the full sheet, drawn, stamped, no scrubber — the honest final state.

**Before → after, recruiter:** before — drag a slider, a picture wipes in. After — the page *draws the drawings in front of you* in an order that clearly means something, then invites you to press play, and the sheet runs like a flipbook. "Human keys, fleet volume, ship" lands without reading a caption.
**Before → after, creative technologist:** before — a linear-gradient `mask-image` and a translating SVG glyph; fine, forgettable. After — view-source shows a vanilla island doing brush-path canvas compositing, pose-to-pose reveal order, a MotionPath pencil with rotation, a 12 fps hold table shot on twos, and an IO-gated rAF loop — five decisions each of which reads as "this person knows both crafts."

## 3. Worked exemplar B — `intent-engineering-mcp`: **"Run the real audit"**

**Communicative intent (unchanged, sharpened):** *most agent failures are intent failures; audit the spec before the agent runs; here is a shipped, domain-verified tool that does it — and it scores its own spec 23/25.* Audience split: a recruiter must feel cause-and-effect (bad spec → wrong build; audited spec → right build); a creative technologist should find a real dev tool, not an illustration of one.

**Where the current build under-serves that intent:** the "spec quality" dial is an abstraction — specs don't improve by turning a knob, they improve by *fixing named sections*; the checklist card is a baked raster of illegible squiggles, so the 9 sections the whole product is about are never actually shown; and the score is a simulated counter easing 7→23. The most impressive fact on the page — *there is a real, deterministic auditor, published on npm, and these numbers come from it* — is currently invisible. (Verified this session: the shipped `audit_intent_spec` is mechanical and instant, returning a score /25, nine per-section findings, anti-pattern flags, and top-3 recommendations — this very spec was run through it; see the verdict block.)

**The realization — choose a spec, watch the real auditor judge it:**

The dial becomes **three real spec cards** on a native radio group (`fieldset` legend: *"Which one would you hand an agent?"* — predict-then-check preserved): ① *the vibe prompt* (two confident lines, no stop rule), ② *the instruction list* (activities, no outcomes — the classic anti-pattern), ③ *the shipped spec* (the MCP's own intent spec — the real 23/25 from the case-study copy). Cards show **live, legible spec text** on rough.js graphite borders (the-block precedent), replacing the baked squiggle rasters. Selecting a card runs the audit: a mono **audit log** streams the real output shape — nine section-verdict lines landing one at a time (`✓ objective — problem-not-solution` / `✗ stop rules — stop.zero-interaction-mandate missing`), anti-pattern stamps thunking in where detected (`⚠ KLARNA INTENT GAP`), the score odometer counting to that fixture's *real* score, recoloring on the existing `--ink-secondary → --teal → --success-teal` ramp. The agent glyph (the existing keyed wrong/right art, retained) flips only when the shipped spec's real result clears — and rough-notation still circles **23/25** in stamp amber. Kicker line under the log: *"This is the audit that shipped on npm — pointed at its own spec."* The case study's best sentence, now performed.

**The provenance mechanism (the part a creative technologist will check):** the checklist items and ids are **imported from the published `@swins/intent-engineering-mcp` package at build time, never hand-copied** — the package's own README declares the SKILL.md canonical and warns that silent forks are the failure mode; a third hand-maintained mirror on the portfolio would be exactly that. If the scorer module is browser-clean, the island bundles it and audits genuinely client-side; if not, a build-time script runs the real tool over the three committed fixtures and emits its verbatim JSON output, which the island replays. Either path keeps the claim honest, and a `validate_content` check enforces it: item count must equal 25 and the three fixture scores must match committed snapshots — a package version bump that changes the checklist **fails the build loudly** instead of silently shipping stale numbers. `[GAP: whether the package's checklist/scorer module imports Node built-ins — decides bundle-direct vs. build-time replay; blocks only the import mechanics, not the design.]`

**Technique and why it fits:** the real scorer (or its verbatim replayed output) is the centerpiece — the "library" that matters here is Sean's own package, which is the strongest possible flex for this audience. GSAP timeline + `typeLines` choreograph the landing of *real DOM list items* (content complete without JS timing — reduced-motion renders the full report instantly, an operability *upgrade* over today's static fallback, per the-block's discrete-state precedent); rough.js and rough-notation are retained as the graphite callout voice. `aria-live` announces score and verdict; the radio group is keyboard-native for free.

**Before → after, recruiter:** before — dragging an abstract slider inflates a number; pleasant, weightless. After — you choose between specs you can actually read, watch a real auditor tear the weak one apart in plain language, then watch the good one pass. "Check the spec before the agent runs" becomes something you *did*.
**Before → after, creative technologist:** before — a simulated counter and baked raster squiggles. After — real checklist item ids in the findings, a build that fails if the page drifts from the npm package, and the self-audit wink executed live. The explainer is no longer *about* the tool; it *is* the tool.

**The other three (later pass, protected this pass):** the pattern generalizes without redesign — code-brain's card migrates from CSS `offset-path` to MotionPath with the same dial (drawn-stroke hand, dawn overture), the-block's routes get DrawSVG wire-draws and a rough-notation tally, 16bitfit adopts `licensedLoop` from the shared module (its own pattern, repaid). ## 4. The intent spec (validated body)

**Objective.** The five `/work/<slug>` explainer graphics under-sell the work. They are the portfolio's highest-leverage five seconds — the "what this does at a glance" figure right after the 4Q — and they currently read as modest slider demos: conceptually right, visually flat, technically shy. That's broken because the band is where the site must *prove* its positioning ("a creative who ships with an agent fleet"), and a basic figure quietly argues the opposite — during an 8-week job-hunt window, to two audiences deciding in seconds. **When facing trade-offs, prioritize communicative intent and structural honesty over spectacle: a beat that doesn't advance the project's one idea — or that displays a number or artifact that isn't real — gets cut, however impressive.**

**Desired outcomes.**
1. A first-time recruiter can state each project's core idea after ≤10 seconds on the band *without interacting* (static floor + one-shot overture carry the meaning; interaction deepens it).
2. Both flagship explainers contain at least one moment a creative technologist recognizes as real technique: the run cycle actually plays as a 12 fps pencil test; the audit is the shipped checklist logic judging real spec text.
3. Every number and artifact on the band traces to a committed real source — verified at build time (`validate`), not by convention.
4. No-JS, reduced-motion, and slow-network visitors get today's experience or better: floors unchanged, zero pre-opt-in bytes added, no new layout shift.

**Health metrics** (each with its adjustment): meaning never gated on interaction → move gated content back to the floor before ship; ≤45 KB gz added JS post-opt-in / 0 pre-opt-in → trending over: switch to anime.js v4 modular or cut a plugin, never ship over; Playwright PE suite extended and green, native inputs, ≥44 px targets, `aria-live` per state → regression blocks ship; anti-template review per beat ("would this fit any project?") → failing beat is cut or rebound to a project-specific artifact; provenance → an unsourced metric fails `npm run validate`.

**The change, with reasoning to carry** (the part a weaker implementing model must not lose):
- *Exemplar A (animation-pipeline):* brush-mask canvas reveal + pose-to-pose order + reader-initiated 12 fps flipbook + one-shot overture, per §2. **Reasoning to carry:** the reveal must read as *drawing* (hatching edge, pencil on the live path) because the medium is the message; the reveal order must be keys → breakdowns → in-betweens because *timing authorship* is the project's claim; the flipbook exists because the project's Engine Truth is a loop that plays — it is reader-initiated media, never ambient decoration, and it reuses the existing committed sheet (no art regeneration is required or permitted by this spec).
- *Exemplar B (intent-engineering-mcp):* three real spec cards → the real auditor's streamed findings → the real scores, per §3. **Reasoning to carry:** the slider dies because "spec quality" isn't a dial, it's named sections passing named checks; the auditor must be the shipped package (bundled or verbatim-replayed) because the honesty *is* the impressiveness — a nicer simulation would be a step backward; the build-time provenance check exists because the SKILL.md's mirror warning names silent forks as the failure mode.
- *System:* `explainer-motion.ts` (loadMotion / wireTimeline / licensedLoop / typeLines), GSAP core + DrawSVG + MotionPath + CustomEase lazy-loaded post-opt-in, scrub-row height reservation, per §1. **Reasoning to carry:** the loader ordering (reduced-motion bail → import → only then `is-interactive`) is the safety property; easing lives in named CustomEase curves because stock curves are where "agency template" leaks in.

**What NOT to change (preservation constraints).** The `ExplainerGraphic` registry contract and unknown-variant degrade-to-`<img>` (a typo'd variant must never break a build). The `explainer:` frontmatter schema. The five static webp floors + alt text + captions — they are the no-JS/reduced-motion truth. The three shipped non-exemplar interactions (code-brain dial, the-block switchboard, 16bitfit drift-lock) — later pass only. The four rollout non-negotiables (dramatize this system; predict-then-check; reader agency; static floor) and DESIGN.md color law (Inversion Rule; stamp-amber the only readable warm on paper). The grounded figures (23/25, 08:30, ~3 hrs/deal, ~6 hrs/week, 12 fps, PIPELINE 47%). The existing `interactive-explainer.ts` exports, byte-identical. And the *paper trail*: the ban lift is recorded — DESIGN.md's licensed-motion registry gains entry (4), the CLAUDE.md/DESIGN.md stack line is amended, and CHANGELOG carries the supersession in the same PR.

**Hard constraints (architecture-enforced, not prompt-trusted):** motion libs unreachable pre-opt-in (single shared loader + an ESLint `no-restricted-imports` rule on `src/components/case-study/*` barring static `gsap` imports); checklist data import-only (build-time package import + `validate_content` count/snapshot check that fails the build); no unbounded playback (`licensedLoop` is the only rAF owner; pause affordance required by its API); native inputs only (asserted by the Playwright PE suite).

**Edge cases:** motion import fails → no `is-interactive`, floor stands, one `console.warn`; checklist import empty/malformed or fixture empty → failed build, never an empty island; brush-path/pose JSON missing at runtime → variant declines interactivity, floor stands; scrub during playback → playback stops, scrubber wins (latest gesture, no dead controls); figure off-screen or tab hidden mid-loop → `licensedLoop` pauses; package version bump changes the checklist → build fails loudly; reduced-motion + intent island → fully operable, instant discrete states, complete report, no stream (pipeline stays today's full-static); touch → native inputs, ≥44 px play control, no hover-only affordances; late enhancement → scrub-row height pre-reserved, no shift. Conflict priority: static-floor meaning > accessibility > honesty checks > weight budget > visual richness.

**Done looks like:** both exemplars render the new scenes behind the existing opt-in contract with byte-identical static floors; `npm run build` and `npm run validate` green including the new provenance checks; the Playwright matrix (no-JS / reduced-motion / interactive / mid-scrub / playing / post-play) green per exemplar; Lighthouse a11y and transfer-weight diffs recorded in the PR; DESIGN.md + CLAUDE.md + CHANGELOG updated in the same PR; and Sean has eyeballed both live and approved — Engine Truth is the final gate. **Stop rules:** halt when a beat needs an invented number (cut it or ask), when the budget can't be met even on the anime.js fallback (re-scope), or when a reduced-motion path would lose operability versus today (redesign). Escalate on low confidence in any Engine-Truth-adjacent visual call (render a preview, ask — don't iterate blind), after **two consecutive failures** of the same automated check (max 2 fix attempts; the third is a conversation, not a retry — the anti-infinite-loop bound), or if the package proves non-browser-clean *and* the extraction fallback can't pin provenance.
