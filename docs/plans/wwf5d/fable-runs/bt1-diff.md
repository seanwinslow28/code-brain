# BT1 diff — Fable vs Opus on skill-audit(intent-engineering)

**Compared:** `fable-runs/bt1-fable.md` (12 findings: 1 DW / 8 S / 3 m) vs `baselines/bt1-opus.md` (9 findings: 2 DW / 6 S / 1 m).
**Method:** identical harness, target, and pinned grounding; both honored the tier1-specs contamination guard. Deltas below are quality-only (style ignored), tagged `dangerously-wrong` / `structural` / `minor`, direction marked **FABLE+** (Fable did it, Opus missed/got wrong — admissible WWF5D evidence per F1) or **OPUS+** (ceiling evidence per F3).

---

## FABLE+ deltas (admissible WWF5D evidence)

- `dangerously-wrong` — **FABLE+ — Opus's spec, implemented as written, silently forks canonical text from shipped code.** Fable read the live `sw-mcp-intent-engineering` server (`checklist.ts`, README) and verified the 25 checklist items are mirrored 1:1 with stable ids in an npm-published package that declares SKILL.md canonical. Consequence carried into its spec: any edit to item wording is a *paired cross-repo change*, with an explicit tripwire ("if you can't make the paired change, file a ticket instead of editing") — and Fable flagged that **its own F3 fix** (rewording the mandate checklist item) triggers this rule. Opus never inspected the server (it deliberately reasoned from SKILL.md text alone), so its spec instructs the implementer to "tighten the Constraint-Quality checklist" and edit Section-9 template text with **zero warning** that this text ships as code elsewhere. A weaker model following Opus's spec faithfully would fork the canonical source on day one — the exact silent, trusted, propagating failure class the audit exists to prevent.

- `structural` — **FABLE+ — Verified-world evidence-gathering vs text-only reasoning.** Fable proactively expanded its evidence base beyond the pinned files to everything the pinned files *claim relationships with*: the target's own `references/intent-spec-template.md`, both consumers' Step-5 contracts at the pinned SHA, and the live MCP server. Opus used the two pinned files plus the battery doc. This is not more reading for its own sake — three of Fable's findings (sync marker, canonical-mandate-text location, tool routing) are impossible to make from the skill text alone, and Fable's adapter findings cite verified shapes (score/25 + findings + top-3; scaffold kinds `blank`/`level-1-mvr`/`full-9-section`) where Opus's cite assumed ones ("align prose output to their contract" — contract never observed).

- `structural` — **FABLE+ — The level-blind checklist seam (validation noise by design).** Fable caught that the 25-item checklist is blind to the retrofit level decided two steps earlier, so an honest Level-1 retrofit *necessarily* fails 13/25 items — which trains the operator to discount validation and is the mechanical root of grounding (c)'s "when is Level 1 enough?" fuzz. Opus caught adjacent findings (the headline MUST-9-sections contradiction, fuzzy level selection) but never that the *validation surface itself* punishes right-sizing — its gate fix ("don't emit until every harm-relevant box passes") would, applied to an L1 retrofit, hard-block every honest small retrofit or force 13 permanent waivers. Fable's F2 (level-scoped checklist keyed off a declared profile line) is the missing piece that makes a validation gate compatible with right-sizing at all.

- `structural` — **FABLE+ — Escalation drops "What NOT to change."** Fable-only finding: both named consumers hold What-NOT-to-change as a floor element, both escalate large fixes to the full 9-section template, and the template has no home for preservation constraints — so protection vanishes precisely when stakes rise. Opus walked the same consumer handoffs and reported "the adapter mostly holds." Fable's fix (a third constraint class inside Section 6, additive so mirrored code survives) is also self-consistent with the cross-repo rule above.

- `structural` — **FABLE+ — Missing output-shape slot, proven by the template's own worked example.** Fable-only: Section 5 records *who* consumes an agent's output but not the *shape*, and the proof is evidentiary, not speculative — Domain Example 2 had to bolt on an "Action Schema" field the template doesn't have. Opus's adapter scan covered the four consumers of the *skill* but never audited the template's own downstream-contract slot for the *agents the specs describe*.

- `structural` — **FABLE+ — Validation as observable artifact state, not behavioral promise.** Both models demand a validation gate. Opus's mechanism is an emission-blocking instruction ("do not emit until..."). Fable's mechanism is a **verdict block appended to the emitted spec** (per-group pass/fail/waived, waive-with-reason semantics, `VALIDATION: SKIPPED (user request)` marker), making an unvalidated spec *visibly different downstream* — enforcement via artifact state rather than promised behavior, which is the target skill's own Key Architectural Insight applied to itself. A behavioral rule dies at the first handoff to a model that didn't read it; an artifact convention is checkable by anyone holding the artifact.

- `structural` — **FABLE+ — Headless / pre-answered grounding path.** Fable-only: write mode's "ask clarifying questions" has no path for pre-supplied answers, yet grounding (d)'s chain ends in a subagent that cannot ask anyone anything — an unconditional ask-first step in headless context either hangs or gets silently skipped. (Fable generalized this from the run's own condition: the battery pre-pins answers for exactly this reason.) Opus's ground→draft fix maps answers to sections but leaves the interactive assumption intact.

- `structural` — **FABLE+ — Tools operationalized, not acknowledged.** Opus's MCP fix states a principle ("treat them as the canonical implementation... align prose"). Fable's routes concrete workflow steps through concrete tools: checklist runs go through `audit_intent_spec` with its output pasted as the verdict block; retrofit sizing goes through `assess_retrofit_level` with its output as the justification line; write-mode scaffolds come from `generate_intent_spec_scaffold` with the exact `kind` names. Fable also resolved the hand-run/tool-run comparability problem (hand reviews adopt the tool's output shape) — Opus left two parallel formats alive.

- `minor` — **FABLE+ — Stale live-count.** Fable caught the hardcoded "107 skills" (twice) against the repo's own live-count convention; Opus didn't flag it.

- `minor` — **FABLE+ — Missing floor-profile worked example.** Fable-only: all four Domain Examples are full agent specs while the skill's highest-traffic incoming job (per grounding (b)) is small improvement specs, so the examples themselves teach over-ceremony. Opus grazed this from the consumer side (its minor size-ladder note) without the examples observation.

## OPUS+ deltas (ceiling evidence — F3; candidates for "cheap on Opus" or Fable blind spots)

- `dangerously-wrong` — **OPUS+ — The unverified-enforcement-mechanism seam. Fable missed it entirely.** Opus's best finding: Section 6 has the drafter *name* an enforcement mechanism ("Never X — enforced via PreToolUse hook"), no step ever existence-checks the named hook/`disallowedTools`/`config.toml` entry, and the checklist item "enforced architecturally" is satisfiable by writing the word "enforced." Owner ships trusting a guard that was never wired. Opus's fix includes the exactly-right epistemic rule for a weaker implementer: *"the word 'enforced' is a claim about the world, and you may only make it after checking the world"* — plus a downgrade path (`PROPOSED enforcement — unverified`). Nothing in Fable's 12 findings covers this. Genuine Fable blind spot on a false-sense-of-safety seam.

- `structural` — **OPUS+ — The write-path mandate-injection trigger gap.** Opus caught that the MUST-inject Zero-Interaction Mandate instruction lives *only* inside the MVR Level-1 retrofit subsection — so a spec written **from scratch** for a launchd agent never triggers injection at all (trigger should key off the Section-7 autonomy determination, not the retrofit path). Fable's mandate finding covered a different face (no canonical text; checklist checks presence not content — the paraphrase-drift failure) but missed the trigger-path gap. The two findings compose (Opus: it never gets injected in write mode; Fable: when injected, the text degrades), but Opus found the sharper production failure.

- `structural` — **OPUS+ — The headline contradiction named as text.** Opus flagged "Every intent spec you write or review MUST include all 9 sections" as directly contradicting MVR Level 1 = 3 sections, with the reading-order mechanism ("a model reading top-down obeys the loudest MUST"). Fable fixed the practice (decision rule, declared profile) but never named the textual contradiction — an implementer of Fable's spec could leave the headline MUST intact and reintroduce the over-ceremony pressure.
