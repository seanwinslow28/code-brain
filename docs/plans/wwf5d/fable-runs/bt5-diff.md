## FABLE+ deltas (admissible WWF5D evidence)

- `structural` — **FABLE+ — Census breadth + explicit counter-checks killed a causal overclaim Opus shipped.** Fable read all 49 manifests (2026-05-02→06-23); Opus read 30 (05-23→). Opus's evidence table calls the weekend clustering "decisive on the *why*": "all 4 error nights are Sat/Sun; every healthy night sampled is a weekday... the weekend-away failure mode." The fuller record falsifies the absolute: the **fifth** error night (2026-05-15, outside Opus's window) is a **Friday**, and Fable explicitly ran the counter-check both ways — "06-20/21 weekend `partial`/`mbp_awake` succeeded; 05-15 was a Friday — the variable is host availability, not weekday" (Phase-3 test 6). Directionally Opus is still right (away/off-LAN dominates), but its "weekend = miss" story is the kind of tidy pattern that steers a fix (its D-recommendation leans on it) one notch harder than the evidence allows. The recipe: before asserting a clustering pattern, widen the census to the full record and hunt for both counter-example directions.

- `structural` — **FABLE+ — Verified the wake system from the live host instead of characterizing it.** Both models identified pmset self-wake as WOL's replacement. Opus *characterized* it ("best-effort... preconditions fail on a meaningful fraction of nights") and deferred verification to the fix ("D2: verify the wake LaunchDaemon is installed/loaded"). Fable *performed* that verification as diagnosis: daemon installed root:wheel 2026-05-22; `pmset -g sched` shows 24 queued wakes now; the scheduler log proves wakes were **queued on every June failure night**; `pmset -g log` proves RTC wakes **fire and hold** at 02:25 when the machine is home (07-02/03/04); `pmset -g custom` power settings. Net: "wakes queued + wakes fire at home + misses anyway" pins the failure to off-LAN/away with measured evidence, exonerates the wake daemon, and pre-answers the fix-time question Opus's spec still carries as a to-do. (Fable also dated the wake-scheduler's origin to the evening after the first miss — reactive patch archaeology.)

- `structural` — **FABLE+ — Dug behind the unwired caller and found the second defect: the corpus void.** Both found lint's `main()` passes no `llm_caller`. Only Fable kept tracing what the leg would do *once wired*: `_build_tier2_prompt` embeds **no article corpus** (instructions + SOUL context only — a wired caller would review nothing), and the LLM block's failure handling is `except Exception: pass`. Opus's wire-it option (B1) as specced ships a scan that scans nothing — its own done-criterion (≥1 `source=llm` finding) would then fail at verification time and strand the implementer one defect short of the goal. Fable's C3 names corpus injection as the sub-requirement "a naive implementation will miss." Recipe: a dead path isn't diagnosed until you've confirmed the path would *work* if revived — wiring, inputs, and error handling are three separate defects that stack.

- `structural` — **FABLE+ — Reconciled the model-identity contradiction; Opus carried it unresolved.** Both knew the 2026-05-26 Ollama/qwen3.6 swap. But Opus's evidence table still reports healthy nights as "`model=qwen3-14b`" without noticing the tension with its own timeline; Fable resolved it mechanistically — `_normalize_model_name` maps any `qwen*` → `"qwen3-14b"`, so the manifest field is a stale enum, the pinned symptom's "Qwen3-14B" is a historical name, and CLAUDE.md's agent table is drifted. The reconciliation matters downstream: manifest-reading tools and humans are currently told a lie by the truthfulness layer itself; Fable's C4 fixes the enum, and its diagnosis corrects the pin as a finding ("the pinned symptom needs two corrections which are themselves findings").

## OPUS+ deltas (ceiling evidence — F3)

- `structural` — **OPUS+ — The loopback repro trap. Fable missed it, and it weakens one of Fable's own tests.** Opus caught that on the MBP itself `seans-macbook-pro.local` resolves to **127.0.0.1** — so any manual run *on the MBP* always sees the target reachable and can never reproduce the production gap; it wired "test from the Mac Mini's resolution path; simulate via `set_machine_status`" into its global invariants. ## The calibration split (the run's most instructive output — feeds WWF5D §6)

Both specs converge on the mechanical fixes (pre-flight once → typed deferral → ≤1 notification honoring config → truthful status → surfaced deferrals; Fable C1/C2/C4 ≈ Opus A/secondary/C). They split on the two **owner-taste forks**:

| Fork | Opus disposition | Fable disposition |
|---|---|---|
| Lint Tier-2: wire it vs retire it | Surfaces both (B1/B2): "the spec surfaces the fork; it does not silently pick" — retire is live because sql/regex has carried every report for months | Pre-decides wire-it, grounding in standing doc intent (CLAUDE.md advertises `soul-tier-a-conflict` as a shipped capability) |
| Host binding: relocate to Mac Mini vs stay on MBP + widen window | Surfaces D1/D2 with recommendation D1 (relocate), contingent on a smaller model clearing `evals/vault-synthesizer/`; "put this decision to the owner" | Pre-decides stay (hard non-goal #3), grounding in v3.14.3's *per-task* rationale — relocation was applied exactly where a small model sufficed, deliberately not here — plus the catch-up-converges evidence; offers C5 window-widening instead |

Neither is sloppy: Opus's discipline is "never silently pick an owner fork" (and it doesn't — it recommends with a named contingency); Fable's discipline is "the record already contains the owner's decision — honor decided intent" (and it cites where). The synthesis rule WWF5D should carry: **pre-make the decisions the record has already made (cite the record); surface the forks where the diagnosis produced *new* tradeoff information the owner hasn't seen — with a recommendation and its contingency, never a bare menu.** By that rule, D deserves surfacing (the weekend/off-LAN evidence is new since v3.14.3) *and* the v3.14.3 quality rationale belongs in the tradeoff table (Opus had the precedent but not the per-task-quality reading; Fable had the reading but closed the door).
