**Compared:** `fable-runs/bt3-fable.md` (14 findings: 2 DW / 9 S / 3 m + 11-row decided-input inventory) vs `baselines/bt3-opus.md` (8 findings: 2 DW / 4 S / 2 m + 12-row custody ledger + 2 cleared paths).

Tags `dangerously-wrong` / `structural` / `minor`; direction **FABLE+** (F1-admissible) / **OPUS+** (F3 ceiling).

**Headline:** the strongest convergence of the battery — both models independently found the same two `dangerously-wrong` seams (artifacts cross the locked stage on assertion + critique fails open; the verdict binds nobody + a gate-failed draft ships polished) and independently invented essentially the same backbone fix (an orchestrator-owned accreting carrier that crosses the voice stage from outside it). ## FABLE+ deltas (admissible WWF5D evidence)

- `structural` — **FABLE+ — Found the contract contradiction, not just the consumption gap (seam beat).** Opus found value-engine fails to consume storytelling's seam beat *by name* (re-derives where value lands) and its fix treats seam-beat ≠ central-loop-close as an anomaly to raise. Fable found the root: **the two stages define the seam beat incompatibly** — storytelling's own canonical example separates PAYOFF (closes the loop) from SO-CAN-YOU (lands the Transfer) as two beats, which *guarantees* failure against value-engine's same-beat rule ("if closing the central loop and landing the Transfer are not the same beat, the seam is bolted-on"). A map built exactly to storytelling's illustrated shape fails value-engine's test on arrival, and no rule says which definition wins. Fable's fix repairs the upstream definition and example AND wires the mismatch back-edge; Opus's fix wires only the back-edge, leaving the upstream example that produces the mismatch intact — the false-BLOCK generator survives its own fix.

- `structural` — **FABLE+ — The reorder license inside the locked file.** Fable-only: `writing-voice-modes`' personal-essay exception ("voice modes lead and format follows... the mode can reshape that skeleton if the piece demands it") textually applies to every Substack chain run, and nothing tells the voice stage that the beat map is not the reshapeable "skeleton" (the clause means creative-writing's format skeleton). Since the file is Tier-1, the disambiguation can only ride in with the map — today it doesn't. This is a hazard *inside* text that cannot be edited, findable only by reading the locked file adversarially for what a weaker in-chain executor could legally do with it. Opus never touched it.

- `structural` — **FABLE+ — Beat-space vs prose-space: nobody owns the coordinate mapping.** Fable-only: the ledger keys loop closure to beat numbers, the voiced draft has paragraphs, and the voice stage *legitimately compresses* beats (its own conflict table endorses compression; merging isn't reordering) — so critique must re-derive coordinates by inference, producing phantom blocking findings that burn the single revise pass, or missed unclosed loops. The fix is surgical: make the ledger's loop *question text* mandatory (already parenthesized in the format) and check closure as "does the draft answer this question?" — prose-checkable — demoting beat numbers to hints. Opus's custody table tracks *whether* artifacts arrive but never audits whether their *coordinate system* survives translation into prose.

- `structural` — **FABLE+ — The post-revise protection hole: the fix list is empty exactly when it matters.** Opus caught the adjacent mechanism gap (findings carry no span anchors, so humanity-pass can't locate fixes). Fable caught the sharper temporal logic: after a successful revise the findings are *resolved*, so a list defined as "findings carried forward + the one fix + verdict" contains **nothing enumerating what the fix changed** — the protection set is empty precisely when a fix was applied, the only time protection matters. Fable also caught that the revise request itself travels naked (no map/Handoff Block/takeaway attached), making the one revise pass the *least* anchored write in the chain. Fable's applied-fix record (finding → quoted changed span) subsumes Opus's span anchors and adds the manifest-rides-along rule.

- `structural` — **FABLE+ — The chain's hardest gate has no machine voice and its verdicts have no route.** Fable-only: value-engine — the only stage empowered to STOP the chain — is the only gate stage with no headless machine-readable verdict format (critique and humanity-pass both define theirs), so a headless drafter pattern-matching for content sails past a prose BLOCK; and both BLOCK and Rule-of-One's "split into separate posts" imply backward routes that don't exist (the chain's only wired back-edge is critique→voice). Opus's custody table shows the verdict crossing to critique but never audits the emission format or the dead-end disposition routes.

- `structural` — **FABLE+ — Per-piece user overrides have no carrier, so the chain reverts Sean's explicit calls by design.** Fable-only, and the most owner-empathetic find in either report: three files carry "unless Sean explicitly asks" exception clauses (suppressed topic, Do-Not-Promote, per-context dial), but no artifact records "Sean authorized X for THIS piece" — so critique's hiring-signal check and humanity-pass's scrub dutifully enforce defaults *against* the authorized exception, burning the revise pass (or a hand-edit) reversing a decision the owner already made. The fix rule for the weaker implementer — overrides must be *quoted, not paraphrased* — is the anti-scope-creep detail. Opus: nothing.

- `structural` — **FABLE+ — The wow-gap scan produced a named, buildable move; Opus dissolved it.** The harness demands concrete missing moves, prioritized. Fable delivered two — the end-of-chain **Intent Thread Check** (one-screen verification block: takeaway welded, every ledger question answered, ask sideways, dial honored, verdict ship, fixes intact, zero dashes/HTML) and loud-degradation-everywhere — with the Thread Check as grounding (d) made literally observable per run. Opus declared its wow-gaps "folded into the structural findings and the Spec's Desired Outcome" — a deliberate collapse that left no end-of-chain verification mechanism anywhere in its spec: its chain still *claims* the thread held; Fable's can *show* it.

- `minor` — **FABLE+ — Forward-pull: function, not punctuation.** Opus explicitly cleared this path (the global dash scan catches any dash regardless of flag survival). Fable read the deeper purpose: the flag exists so the dash gets replaced *while keeping the pull* — humanity-pass replaces dashes mechanically without knowing which line is a load-bearing section-ender, so a pull line becomes two clean sentences and the section ends in exactly the "clean summary that gives the reader permission to stop." Opus's clearing verified punctuation compliance and missed function preservation — an auditable, well-reasoned wrong conclusion.

- `minor` — **FABLE+ — The publish surface itself.** Fable-only: headless deliverables end in HTML comments (change summary, verdict block) and no stage owns stripping them, so pipeline internals land in the published post's source/RSS — in front of the exact recruiter audience the hiring-signal rules are calibrated for. Plus the scaffold-choice carrier gap (critique told to defer to a scaffold nobody names to it). Small, real, one-line fixes.

- `minor` — **FABLE+ — Finer failure semantics at the degraded gate.** Both invert "when present" into required-in-chain-mode. Opus's absence semantics: missing ledger/verdict = blocking `structural-rework` (hard stop). Fable's: proceed with the degraded check, name the loss, and **cap the verdict at `revise`** — never `ship` un-anchored. Fable's three-state design (anchored / loud-degraded / never-ship) keeps the recoverable case recoverable (re-supply the manifest, re-run) while still killing the dangerous outcome; Opus's two-state treats a transport loss as chain-fatal even when the fix is a one-line re-supply.
