## Tier 2 rationale

- **creative-writing** — Sean's blog/LinkedIn/portfolio-narrative workhorse for the job hunt; pairs directly with the Tier-1 writing-voice-modes, and its generic-template output has real wow-gap headroom.
- **daily-driver** — highest-frequency non-locked skill (runs every morning + EOD, ~36 CHANGELOG touches); skill-audit was literally built with it as the worked example, so improvement is cheap and high-yield.
- **prd-generator** — named swap-bench skill; the core PM artifact for a PM in an active job hunt, interview-driven and fully SKILL.md-improvable this window.
- **prompt-engineering** — named swap-bench skill and a meta-skill (Leverage up): improving how prompts get written improves everything downstream Sean builds.
- **screenwriting-modes** — voice-and-taste calibrated to Sean (same improvement surface as writing-voice-modes); creative-studio is one of two active domains, so the wow-gap on "sound like me" matters.
- **storytelling-architecture** — stage 1 of the Substack chain Sean runs constantly; pure instruction content, so skill-audit can sharpen the beat-map output directly.
- **substack-value-engine** — stage 2 Value Gate of the same chain; gates whether a post is worth shipping (high leverage on all published writing) and is instruction-only.
- **technical-writing** — produces exactly the portfolio artifacts filling the ticket backlog (READMEs, runbooks, EXPLANATIONs, RFCs); generic craft output has clear headroom and improves cheaply.
- **writing-critique** — named swap-bench skill and the chain gate between voice and humanity passes; actively used and refined, so tightening its triage output pays off immediately.
- **writing-humanity-pass** — final stage of the Substack chain, run on nearly every draft (agent or human); de-slop quality directly gates what reaches recruiters.

## Scoring notes

- Scores are **Opus estimates inferred from repo signals** — the agents-sdk schedule tables and MCP inventory in `CLAUDE.md`, `CHANGELOG.md` investment frequency (skill-name mention counts), the open-ticket backlog in `vault/00_inbox/tickets.md`, and local memory files — **for Sean to confirm or adjust**, not measured telemetry. Frequency in particular is a proxy (how often a skill shows up in recent work), not a usage log.
- **High-frequency skills deliberately left in Tier 3** (fusion-discovery-council, llm-council, last30days, gemini-deep-research, vault-read-write): these are used heavily but their quality lives in external Python engines, not the SKILL.md that skill-audit sharpens, so this window's cheap-model editing has low leverage on them. fusion-discovery-council is additionally mid-flight in active development (large open-ticket backlog) — editing its SKILL.md now would collide. They are Tier 3 by *improvability this window*, not by importance; they are prime Phase-C spec candidates.
- **The two brand-new skills** (skill-audit, zoom-out-and-think) score high on Leverage (both are meta) but Frequency is prospective and Wow-gap is unknown — they were just built to spec in Tasks 1–2, so they sit in Tier 3 this window by design, not because they rank low.
- **Tier 1 is locked** to the five named skills regardless of raw score; no swaps.
- `wwf5d` (created 2026-07-04, after this triage) is deliberately absent from the table: it is the WWF5D output container filled by Fable in Phase B, not an improvement candidate. The completeness check's denominator was the 127 skills present at triage time.
