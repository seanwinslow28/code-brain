# taxonomy — rung 1 of the ladder, content machine

The tracked vocabulary the labels file's `failure_code` column draws from. One file per studio (the kit's rule; Productcraft's is [`productcraft/trace/taxonomy.md`](../../../../productcraft/trace/taxonomy.md)); this is the content machine's. Shapes of failure only — no run content, no transcript line, no draft, nothing of his.

**Rung 1 is not open.** The ladder is deterministic checks first, a taxonomy after about thirty labels, a judge only for a mode that recurs with 30–50 labels per class validated on TPR/TNR ([#272](https://github.com/seanwinslow28/code-brain/issues/272), translated to the machine on [#261](https://github.com/seanwinslow28/code-brain/issues/261)). No run has been labeled through the kit yet, so this file holds the table's shape and nothing in it: `check.py` reads an empty table as an unopened rung, and any code in a labels file is a finding until a row exists here.

**What is already known about the shapes, unnumbered.** Two real decks have been judged by hand before the kit existed ([#255](https://github.com/seanwinslow28/code-brain/issues/255), [#258](https://github.com/seanwinslow28/code-brain/issues/258)): four of eight cards cut for landing *against the frame the poster posted in*, traced to the shaper faithfully imitating the ~20% of its own samples that dunk. That is a sighted shape, not a code — it earns a row when the labels file names it as the lead shape of a fail, with a count.
